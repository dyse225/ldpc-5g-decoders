# Виолета: QPSK и итеративные LDPC-декодеры

Эксперимент выполнила Виолета. Владимир Дьяченко подготовил сохранённые данные для командной сводки. Для обоих графов используйте `analysis/combined_results.mat` (массив ячеек `runs`, поля `meta` и `res`) или `analysis/raw_results_both_bg.csv`. Исходный `results/all_results.mat` содержит последний прогон BG1. Общий набор собран из 22 файлов основного кэша, включая два прогона без кодирования. Параметры и графики экспериментальных прогонов доступны в `results/`.

При QPSK, AWGN, R = 1/2 и лимите 50 итераций получены следующие пороги Eb/N0 при FER = 0,01 (дБ, логарифмическая интерполяция).

| Граф и длина | Layered BP | BP | OMS | NMS |
|---|---:|---:|---:|---:|
| BG1, K = 3872 | 0,86 | 0,91 | 1,05 | 1,12 |
| BG2, K = 520 | 1,52 | 1,56 | 1,63 | 1,68 |

Для Layered BP увеличение лимита с 5 до 20 итераций снижает требуемый Eb/N0 на 1,44 дБ у BG1 и на 1,07 дБ у BG2. Переход с 20 до 50 даёт ещё 0,10 и 0,08 дБ соответственно. При сравнении графов учитывайте разную длину информационного блока.

Для NMS и Layered BP есть кривые при 5, 10, 20 и 50 итерациях. BP и OMS рассчитаны только при 50. Подбор α и β проведён при 50 итерациях. В основных прогонах использованы α = 0,65 и β = 0,60 для BG1, α = 0,75 и β = 0,55 для BG2. Отдельный подбор для 5, 10 и 20 итераций остаётся открытой частью задачи.

Все пороги приведены в `analysis/summary_both_bg.csv`. NaN означает отсутствие пересечения между соседними положительными измеренными точками. Для каждой строки с нулём ошибочных кадров в таблице измерений приведена верхняя односторонняя 95%-ная граница FER. Скрипт `analyze_saved_results.py` собирает таблицы из кэша и сверяет BER/FER со счётчиками ошибок.

## Исходное описание эксперимента

# qpsk_ldpc_iterations: 5G NR LDPC, QPSK, влияние числа итераций

Моделирование итеративных декодеров LDPC 5G NR: **BP (flooding), Layered BP, NMS, OMS**.
QPSK (Gray, 2 бита на символ), канал AWGN, R = 1/2.
Коды: **BG2 (Zc = 52, K = 520)** и **BG1 (Zc = 176, K = 3872)**.
I_max = 5, 10, 20, 50. Метрики: BER, FER, среднее число итераций.

Положить папку в `matlab/experiments/`. Используются общие `ldpc_simulate.m` и
`ldpc_default_params.m` (не изменены). Нужны MATLAB, Communications Toolbox, 5G Toolbox.

## Запуск

`run_all.m` выполняет четыре этапа подряд и по умолчанию использует пресет `'standard'` для итоговых графиков.
Для быстрой проверки всей цепочки (сокращённые сетки Eb/N0 и число кадров) вручную замените настройку на `qli_config('quick')`.

| Этап | Функция | Что делает |
|---|---|---|
| 0 | `qli_check_llr` | проверка пересчёта Eb/N0 -> SNR (`convertSNR`) и LLR для QPSK |
| 1 | `qli_find_params` | поиск оптимальных α (NMS) и β (OMS) при I_max = 50 |
| 2 | `qli_run` | основной свип: 4 декодера x I_max, uncoded QPSK; CSV |
| 3 | `qli_plots` | все графики задания для каждого BG |

Если BG1 не успевает, поставьте `cfg.bgList = 2;`. Все параметры (Zc, I_max, сетки Eb/N0, число кадров,
рабочие точки для α/β, `parallel`) — в `qli_config.m`. Готовые прогоны кэшируются в `results/cache`,
прерванный запуск можно продолжить.

Графики сохраняются в едином оформлении: белый фон, увеличенный размер полотна, шрифт осей 11 pt,
контрастные линии с маркерами, дополнительные линии сетки и разрешение PNG 200 dpi.
Режим `quick` предназначен только для проверки работоспособности: из-за малого числа кадров и редкой сетки
Eb/N0 его кривые могут быть менее гладкими и содержать пропуски при нулевом числе зарегистрированных ошибок.

## Технические нюансы

- **Eb/N0 -> SNR.** `ldpc_simulate` вызывает `convertSNR(Eb/N0, "ebno", "snr", BitsPerSymbol=2, CodingRate=R)`,
  где R = K/E — реальная скорость после согласования. Es/N0 = Eb/N0 + 10·log10(2·R); для R = 1/2 они совпадают,
  у некодированной QPSK Es/N0 = Eb/N0 + 3,01 дБ.
- **LLR для QPSK.** Для Gray-QPSK с единичной мощностью LLR бита по оси равен 2·√2·Re(y)/nVar (nVar — полная
  дисперсия комплексного шума), то есть по формуле BPSK с учётом амплитуды 1/√2. Формулу я проверил
  независимо (точный LLR перебором точек созвездия, критерий E[exp(−LLR) | бит 0] = 1). `qli_check_llr`
  проверяет то же для реальных `awgn`/`qamdemod` и знак (LLR > 0 — бит 0).
- **Оптимальные α и β.** Ищутся при I_max = 50 в рабочих точках `cfg.param.EbN0dB` (FER ~ 1e-1…1e-2) по среднему
  log10(FER) со сглаживанием по трём соседним значениям; в `param_optimum.csv` — плато значений в пределах 1σ.
  Можно задать вручную: `cfg.alphaOpt = struct('bg2', 0.8, 'bg1', 0.8)`.
- **Экономия времени.** Все четыре I_max считаются только для NMS и Layered BP (как в задании); BP и OMS — при I_max = 50.
  Чтобы посчитать I_max для всех, добавьте их в `cfg.iterDecoders`.
- **Одинаковые кадры.** Во всех прогонах один seed, поэтому кривые для разных I_max и декодеров считаются на одних и тех же кадрах.
- Перемежителя перед модулятором нет, согласование скорости упрощённое (как в общем `ldpc_simulate`).
